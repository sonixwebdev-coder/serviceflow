# Security policy

## Supported versions

Until the first stable release, security fixes are applied to the latest commit on the default branch. After versioned releases begin, this file will list the supported release lines.

## Reporting a vulnerability

Use GitHub's **Private vulnerability reporting** for this repository. Do not open a public issue, discussion, or pull request containing vulnerability details, credentials, personal data, or an unreleased proof of concept.

Include the affected version or commit, relevant configuration, impact, reproduction steps, and any suggested mitigation. Reports should test only systems and data you own or are explicitly authorized to assess.

Maintainers will acknowledge a report when it is reviewed, coordinate validation and remediation privately, and publish an advisory when users need to take action. No response-time or bounty commitment is currently offered.

## Operational responsibility

Operators must replace all example secrets, use supported dependencies, terminate TLS, restrict administrative access, configure backups, and keep deployment-specific legal and privacy information current. Example configuration is intended for local development unless explicitly documented otherwise.
